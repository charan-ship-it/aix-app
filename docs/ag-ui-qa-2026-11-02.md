# AG-UI and CopilotKit observer — verification, 2 November 2026

## Delivered scope

The existing `/work/[runId]` page now mounts a scoped, code-split CopilotKit headless observer. It consumes AG-UI through the standard self-hosted CopilotKit runtime and updates the page from the canonical safe `state.work` snapshot. Actual Redis response text can appear as a transient preview until the worker saves the durable result. Recorded tool names/status are shown without forwarding raw tool credentials or inputs.

This is a work-detail interaction slice. The main conversation composer retains its existing stream. Existing AIX records, execution, approval, cancellation, review and source permissions remain authoritative. No new model harness, provider account, queue, memory service, thread database, sandbox or ongoing responsibility was introduced. The [meeting feedback](product-feedback-2026-11-02.md) remains separate implementation work.

Pinned packages are AG-UI core/client/encoder **1.0.2** and CopilotKit React/runtime **1.83.0**. The standard self-hosted runtime avoids the Enterprise `selfManagedAgents` path and unsafe development registration. No Intelligence/public API/license key is configured, and no frontend execution tool or model fallback is registered. Supported telemetry opt-out is set in Docker and the runtime; Scarf installation analytics is disabled in Docker.

## Automated and build evidence

- **82 automated tests passed**: `outputs/ag-ui-tests.log`. Stream tests cover protocol schema validity, safe snapshots, read-only input handling, bounded observation, genuine recorded updates and access checks around asynchronous delivery.
- TypeScript passed: `outputs/ag-ui-typecheck.log` and independent `outputs/ag-ui-acceptance-typecheck.log`.
- Production Docker app/worker build passed: `outputs/ag-ui-build.log`. The coordinating agent verified healthy app/PostgreSQL/Redis services and a running worker, with `COPILOTKIT_TELEMETRY_DISABLED=true` in the app container.
- **Six actual HTTP/SDK acceptance groups passed**: `outputs/ag-ui-api.log`. Run with `node tests/ag-ui.integration.ts` on Node 24. The script uses native TypeScript stripping and direct declared PostgreSQL/Redis clients for disposable fixtures; it does not use `tsx` or patch SDK dependencies.
- All **16 existing HTTP regression groups passed**: `outputs/ag-ui-regression-api.log`. `npm run test:ag-ui:http` now provides the native SDK acceptance command.

The six HTTP groups establish:

1. The installed AG-UI `HttpAgent` consumes schema-valid completed, interrupted, cancelled and failed lifecycle streams. Its request/result comes from the exact canonical run, excluding internal model/session/credential data and later conversation turns.
2. Member/tenant ownership, canonical URL-selected work, exact thread binding, separate observation identity and same-origin POST protection hold.
3. Forged client history/state cannot mutate durable work. Tool/context/resume/forwarded authority is rejected and existing approval state remains unchanged.
4. Current project and organization-membership revocation deny a new observation after an earlier successful read.
5. The actual installed client consumes controlled Redis text/tool events, then replaces the preview with the saved result. Raw live credential markers are absent and reconnect does not duplicate the final assistant message.
6. The installed CopilotKit `ProxiedCopilotRuntimeAgent` consumes the authenticated standard runtime. Information and run routes share private access checks; forged thread/tools and unsupported stop/connect/thread-store routes are rejected.

The script created and removed isolated synthetic accounts, organizations, conversations, runs and Redis event keys. It did not call a live model, connector tool or queued agent job. A first run exposed a fixture-order mistake: the test expected an active-member ownership response after deliberately revoking that member. The fixture was corrected, and the full script then passed without weakening authorization.

## Independent review findings corrected

- The installed provider's `selfManagedAgents` path carries an Enterprise production licensing warning. The implementation uses the supported open-source runtime rather than bypassing that distinction.
- The first live preview selector looked only for a saved-result message ID. It now recognizes the current run's scoped live-message prefix, so genuine streamed text is visible.
- Legacy concurrent tool events provide names without reliable provider call IDs. Ambiguous results are explicitly marked as uncorrelated rather than guessed by array order.
- Runtime requests validate and sanitize observation input before framework middleware. Authenticated client state does not become prompt, tool or execution authority.
- SDK imports work natively under Node 24, while the `tsx` loader redirects `fast-json-patch` to an unusable published TypeScript source stub. Acceptance therefore uses the actual installed SDK under the native loader, not a dependency patch.

## Remaining limits

No full chat migration, selectable harness, model subscription bridge or live model quality is certified by this slice. Existing AIX approvals remain separate explicit decisions; a paused observation does not approve an action. Detaching or hiding the update panel closes observation rather than cancelling the business run. Terminal work rechecks access on focus/refresh; this does not claim instant removal of content already rendered in a browser.
