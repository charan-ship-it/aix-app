# AIX architecture and product audit — 29 October 2026

This is a source-level audit and feedback record, not a certification that every integration or model run works. It consolidates the repository inspection and the user's feedback from the ongoing build. Implementation status is tracked in [the feedback backlog](feedback-backlog.md); the framework boundary is recorded in [ADR 0001](adr/0001-selective-agent-frameworks.md).

## Assessment

Follow-through, 30 October 2026: the streaming access gap is fixed and a private all-project conversation index is implemented. See [history/access verification](history-access-qa-2026-10-30.md) and the current backlog for remaining scope. Original findings below describe the inspection baseline.

AIX has a coherent working foundation: a Next.js web/API application, a separate background worker, PostgreSQL/pgvector, Redis/BullMQ, Better Auth organization membership, Drizzle persistence, and AI SDK agent execution. It is not yet a clean, production-hardened release baseline. Product behavior and execution evidence are too fragmented for a user to understand ongoing work without coaching.

The product is a configurable AI workforce platform. An agent harness is an implementation layer inside it. The target experience is: describe a responsibility → grant scoped access → rehearse → enable a trigger or schedule → inspect results and decisions → improve deliberately. A saved agent configuration alone does not establish that loop.

## Actual architecture

| Layer | Current source | Responsibility |
| --- | --- | --- |
| Web and API | [`app`](../app), [`components/product`](../components/product) | Product routes, editor, chat, connection and review screens |
| Identity | [`lib/auth.ts`](../lib/auth.ts), [`lib/server/http.ts`](../lib/server/http.ts) | Sessions, active organization, current membership and role |
| Persistence | [`db/schema.ts`](../db/schema.ts), [`postgres-migrations`](../postgres-migrations) | Shared workspace records, member-owned runs, credentials, schedules and knowledge chunks |
| Agent harness | [`lib/server/runtime.ts`](../lib/server/runtime.ts) | Resolve agent/skill/Pod context, persist execution, model/tool loop, approvals, cancellation |
| Delegation | [`lib/server/delegation.ts`](../lib/server/delegation.ts) | Bounded parent/child runs, allowlists, deduplication and parallel results |
| Background execution | [`worker.ts`](../worker.ts), [`lib/server/queue.ts`](../lib/server/queue.ts) | Indexing, agent, schedule and evaluation queues; one worker process with separate concurrency settings |
| Knowledge | [`lib/server/rag.ts`](../lib/server/rag.ts) | Chunking, keyword retrieval and optional OpenAI embeddings/vector search |
| Integrations | [`lib/server/composio.ts`](../lib/server/composio.ts), [`lib/server/mcp.ts`](../lib/server/mcp.ts) | Member-scoped Composio identity; organization-shared MCP connection credentials |
| Learning and evals | [`lib/server/learning.ts`](../lib/server/learning.ts), [`lib/server/evals.ts`](../lib/server/evals.ts) | Private feedback, explicitly shared candidates, assertion tests and immutable publication |

Agents, conversations, runs and Pods are distinct entities. An agent defines behavior and access; a conversation contains messages; a run is one execution; a Pod supplies project context and access rules. Skills supply reusable procedures and do not grant new tool permissions.

## Findings requiring follow-through

### Repository and release maintenance

- At inspection, Git reported 101 deleted, 69 untracked and 18 modified status entries. Some entries represent directories, not individual files. No files under the current `lib/server`, `tests`, `postgres-migrations` or `components/product` paths were tracked in that baseline. The current development checkout therefore exceeds what a fresh clone of the committed source reproduces. Preserve existing work; do not reset or delete it as cleanup.
- No checked-in `.github` CI workflow was found. [`package.json`](../package.json) has build/typecheck/test commands but no integrated API-test, lint or formatting gate.
- The UI retains overlapping generations. At inspection, `app/workspace.tsx` was 2,486 lines, `quality-workspace.tsx` 1,513, and `agent-studio.tsx` 1,072. `ProductApp` embeds the older workspace through `productMode`. Consolidation should be incremental and covered by journey tests.
- [`tests/browser/workspace.spec.ts`](../tests/browser/workspace.spec.ts) still expects the older modal builder, button navigation and `.employee-rail`. Its existence does not make the current routed product browser-tested.
- Most application entities share JSONB `workspace_record` records. Tenant isolation is application-enforced, not backed by PostgreSQL row-level security. This is an architectural tradeoff that increases the importance of consistent access helpers and regression tests.

### Permissions and source provenance

- **Streaming access gap:** [`app/api/runs/[id]/events/route.ts`](../app/api/runs/[id]/events/route.ts) checks organization and run ownership, but does not perform the current Pod authorization used by [`readConversation`](../lib/server/conversations.ts). Its terminal fallback can return chat data after Pod visibility has changed. Fix entry and long-lived stream revalidation; test Pod and membership revocation as well as cross-tenant callers.
- **Shared Scribe access is not personal meeting ownership:** `openStoredMCP(organizationId, id)` opens a connection using its organization-shared token. It receives no initiating member identity. A source token may authorize organization-wide meeting access; participation or calendar presence does not prove recording ownership or transcript rights.
- The inspected Vaani record identifies a host and manual source, but no recorder-owner field. Participant emails are absent. Do not label these records “my meetings” or infer personal assignment from attendance alone.
- A source's `has_transcript` flag is insufficient evidence that usable text is available: a live read returned an empty transcript for one meeting. Validate the actual response before extraction.

### Work entry, history and activity

- New chat defaults to `xcelerate` in [`ProductApp`](../components/product/product-app.tsx); choosing a specialist is not technically mandatory. The prominent agent selector and separate builder nevertheless communicate an agent-first setup experience.
- Home chat posts a run request; it has no agent-creation action. AI-assisted drafting exists separately in [`/api/agents/draft`](../app/api/agents/draft/route.ts). Bridge a goal into a reviewable draft and reuse the existing save path rather than silently adding creation powers to every specialist.
- The global workspace response excludes Pod records, the sidebar shows up to 16 non-Pod chats, and an agent page shows five recent chats from that global data path. A complete private history index needs a new authorized query across accessible Pods; merely displaying the existing array will retain omissions.
- Missing-provider attempts stop before enqueueing and leave a browser draft, not a saved chat or run. Show an explicit blocked/draft state and a return path without fabricating a model execution.
- Direct MCP reads and reasoning performed in this Codex session bypass the AIX runtime. They do not automatically appear in product history or activity. Any retained assisted result needs an explicit provenance type; never insert a fake completed model run to fill an empty screen.
- [`DelegatedWork`](../components/product/delegated-work.tsx) is a conditional strip within an existing conversation. It shows child links/statuses, swallows load errors, and is not a workspace orchestration console. Users need parent/child progress, approvals, reasons for pauses, failures and results in one discoverable view.

### Autonomy and orchestration

- Scheduled agent execution exists in [`scheduler.ts`](../lib/server/scheduler.ts), and browser-independent work exists in the background worker. Local work still depends on the host and Docker running; the prepared Railway configuration is not an actual always-on deployment.
- No transcript-ready or meeting-completed ingestion/webhook flow was found in `app`, `lib` or `worker.ts` during this audit. General cron prompts do not provide a permission-aware after-meeting workflow.
- Agent Workflow-tab steps are ordered model instructions. They are not independently deployed deterministic jobs.
- Product delegation is bounded research/drafting: at most two child handoffs, child external app/MCP tools removed, no recursive delegation, restricted knowledge, approval before launch, separate durable run/conversation, and cancellation/partial-failure handling. Child execution is inside the parent worker path, not an independently scalable child queue.
- Development subagents used to build the repository are distinct from product specialists. Development activity must not be presented as customer-visible AIX execution.

### Tests and learning

- The tests include meaningful database/Redis checks and local HTTP provider fixtures that exercise actual SDK transport. Those controlled responses prove execution wiring, not live model quality.
- Tests use fixture organizations in the configured PostgreSQL database; several use separate Redis databases. The HTTP integration script briefly pauses the actual local agent queue. Move repeatable release checks to disposable infrastructure rather than a shared developer stack.
- Current evaluation calls are tool-free skill-instruction comparisons with literal assertions. Publication recomputes assertions and checks exact candidate/baseline/suite hashes and revisions. Preserve these safeguards while adding retrieval and complete-task outcomes. Do not describe this loop as foundation-model training or guaranteed autonomous self-improvement.

## Current selective-framework change

Verification update, 30 October 2026: the authorized embedded slice is **implemented and verified locally**; see [verification evidence](selective-framework-qa-2026-10-30.md). It adds an opt-in native `extract_transcript_actions` capability backed by a Mastra workflow for input validation, AI extraction, evidence validation and deterministic result rendering. It is called from the existing AI SDK agent runtime. It does not replace Next.js, authentication, Drizzle, PostgreSQL, BullMQ, chat persistence, MCP access or Composio.

This bounded integration is not evidence of an automatic transcript trigger, a new permission model, general autonomous work, or product parity with other assistants. See [ADR 0001](adr/0001-selective-agent-frameworks.md) for ownership boundaries and rollout criteria.
