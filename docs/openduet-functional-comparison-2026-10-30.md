# OpenDuet functionality compared with AIX

Reviewed 30 October 2026. AIX remains its own repository and product. This is a source review for useful behavior, not a migration proposal or a claim of feature parity.

OpenDuet reference: `Ai-Xccelerate/openduet`, main commit `25f9262794659ac144d10505253b553ef5afff06`. Source files below were read through GitHub's API. No OpenDuet installation, browser session, test suite, live connector action or model evaluation was run in this review. “Implemented” means concrete source was inspected; it does not mean operationally verified here. AIX references are local files, with verification limits stated separately.

## The most useful similarities and gaps

| Customer experience | OpenDuet source evidence | AIX today | Useful next step for AIX |
| --- | --- | --- | --- |
| Ask in chat, then follow a separate piece of work | [`tasks.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/openduet/tasks.ts) implements task-creation and task-start tools. A started task receives its own conversation and a card linking back to it. [`task-store.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/openduet/task-store.ts) derives statuses for work in progress, input needed, review, failure and acceptance from execution records. | Separate agent chats, durable runs, private conversation history, My work and Pod tasks exist. [`lib/server/delegation.ts`](../lib/server/delegation.ts) gives allowed specialists linked child conversations/runs, bounded to two and without further delegation or external app access. These pieces are not yet one obvious customer task journey. | Create one task detail destination linking request, run, approvals, result and continuation. Derive execution state from runs rather than another independently mutable status. Keep personal work private. |
| Keep working without an open browser | [`routines/sweep.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/routines/sweep.ts) offers due occurrences with a stable key and leases. [`routines/runner.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/routines/runner.ts) checks pause/access, records outcomes and waiting states, and disables a routine after ten consecutive failed firings. | [`lib/server/scheduler.ts`](../lib/server/scheduler.ts) and [`worker.ts`](../worker.ts) implement BullMQ schedules, occurrence identities, retries, current creator membership checks and durable failed-start records. A general ongoing-responsibility experience and repeated-failure fatigue policy are still gaps. | After a successful first job, offer a schedule with destination, owner, limits, pause and inspectable last outcome. Add an explicit repeated-failure policy and notification behavior. |
| React to an event | [`responsibilities/triggers.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/responsibilities/triggers.ts) defines narrow trigger configurations; [`responsibilities/engine.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/responsibilities/engine.ts) claims leased work, checks paused agents, renews leases, cancels on lost lease and records success/waiting/failure. This review did not certify every ingress signature path. | AIX schedules are real, but a general authenticated event-to-responsibility pipeline is not established by the reviewed local source. Connecting Gmail is not evidence that incoming mail starts work automatically. | Add one event source first with sender verification, deduplication, owner/account scope, pause behavior and an event-to-run audit trail. |
| Approve an exact action and continue safely | [`approvals/execute.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/openbot/server/src/approvals/execute.ts) rechecks conversation access and available tools, resolves the credential actor again, and handles connector, computer and coordination continuations separately. | [`lib/server/runtime.ts`](../lib/server/runtime.ts) persists pending tool approvals and resumes runs; MCP calls require approval. AIX's worker/run model already supports this foundation. A broad browser/computer execution capability is not implemented merely because developers can use a browser during QA. | Put approvals and blockers in the task journey, with the exact action/account visible. Preserve access rechecks on resume and do not infer permission from an old approval. |
| Improve quality using measured cases | [`evals/triage/run.ts`](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/evals/triage/run.ts) calls the production triage implementation against labeled synthetic mail and calculates precision/recall. Its [README](https://github.com/Ai-Xccelerate/openduet/blob/25f9262794659ac144d10505253b553ef5afff06/evals/triage/README.md) reports historical scores and explicitly limits the small invented dataset; those scores were not reproduced here. | [`lib/server/evals.ts`](../lib/server/evals.ts) supports versioned suites and model evaluation; [`lib/server/learning.ts`](../lib/server/learning.ts) gates publishing an exact skill candidate on an eligible evaluation with no regression. Live model quality has not been established for the first-task flow while model access is absent. | Add outcome-specific labeled cases for follow-up relevance, owner attribution, deadline evidence, missed important mail and unsafe proposed actions. Feed reviewed user corrections into candidate cases; do not silently change shared prompts from one person's feedback. |

## What this changes in the product plan

The valuable pattern is the complete loop: request → separate work item → visible execution/input needed → evidence-bearing result → user acceptance → optional ongoing responsibility. AIX has several of these foundations, but their connections and first-use clarity are incomplete. The current home/onboarding slice addresses entry and return paths; it does not claim the full loop is finished.

Retain AIX's Next.js, PostgreSQL/Drizzle, Redis/BullMQ, AI SDK and bounded Mastra workflow pieces. Borrow contracts and interaction patterns selectively. The next substantial runtime slice should unify task/run/result navigation, then connect one proven job to one scheduled or event-driven responsibility. Keep software-factory automation and coding-agent access as explicit separate backlog items until implemented and exercised.

For AIX verification evidence, see [history/access QA](history-access-qa-2026-10-30.md), [selective framework QA](selective-framework-qa-2026-10-30.md), and the [feedback backlog](feedback-backlog.md). Local deterministic/API checks certify their stated boundaries, not OpenDuet behavior or live-model accuracy.
