# AIX consolidated feedback backlog

Updated 2 November 2026. This is the source-of-truth backlog distilled from the user's feedback, [the source audit](audit-2026-10-29.md), and [meeting feedback](product-feedback-2026-11-02.md). **Existing** means there is an implementation to preserve; it does not certify the whole journey. **Open** means unfinished. **In progress** means changes are not yet accepted as complete. Historical QA reports are evidence with stated scope, not blanket completion.

Priorities: **P0** = access or execution trust boundary; **P1** = a first useful, returnable job; **P2** = broaden dependable work; **P3** = distribution/launch expansion. Work may proceed independently when it does not depend on an unresolved boundary. Do not reset existing work or migrate the whole application to a framework.

### Roadmap and dependencies

1. **Trust and baseline:** OPS-01, TRUST-02–04, ACCESS-01 and TEST-01. UX fixes can proceed alongside this work without weakening the boundaries.
2. **One dependable job:** ONBOARD-02, MEET-01, CONNECT-01/02, TIME-01, HISTORY-01 and ACTIVITY-01. Include clear chat titles and the agent-home/builder improvements above.
3. **Visible coordinated work:** TEAM-01 and HARNESS-01. Existing bounded delegation and the AI SDK runtime are foundations; prove permission, recovery and activity visibility before offering more adapters or autonomous teams.
4. **Ongoing work and team scope:** RUN-02, MEET-02, SCOPE-01 and TEAM-02. Define triggers, source access, limits, stopping and explicit sharing before expansion.
5. **Broaden the platform:** RUN-01 and COST-01 (funding and supported provider options); BROWSER-01 and SANDBOX-01 (isolated execution); CHANNEL-01 (communications); FACTORY-01 and DEV-01 (coding-agent bridge and software factory); OPS-02 and PRODUCT-01 (deployment and customer validation).

TRUST-01 and ACTIVITY-02 have historical local verification below and remain regression targets, not new open tickets. See [product feedback](product-feedback-2026-11-02.md), [interface audit](interface-audit-2026-11-03.md), and [AG-UI decision](adr/0002-ag-ui-interaction.md) for context; they do not create separate competing backlogs.

## Delivery checkpoints (existing foundations)

1. Preserve a reproducible baseline and close trust boundaries.
2. Complete a returnable transcript job with visible source scope, progress, table and history.
3. Complete a visible bounded coordinator/parallel-specialist job.
4. Add automatic responsibility triggers and notification only after source access and execution states are proven.
5. Broaden evals, browser/channel automation and production operations without replacing the platform wholesale.

The selective Mastra slice addresses only part of **MEET-01**. The saved transcript agent was updated and reloaded in the browser. See [verification evidence](selective-framework-qa-2026-10-30.md). It does not close **MEET-02**, **RUN-02**, personal Scribe authorization, live model quality or the history/activity backlog.
